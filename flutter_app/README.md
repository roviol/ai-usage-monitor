# AI Usage Monitor — Flutter application

Flutter desktop application (Windows + Linux) that mirrors the C++/wxWidgets
reference application in this repository with functional parity: same providers,
same parsers, same metrics, same settings/cache files, same scheduler behavior
and the same status text. Visual styling may differ; behavior and data may not.

## Commands

- Lint: `flutter analyze`
- Tests: `flutter test`
- Run: `flutter run -d linux` (or `-d windows`)
- Release build Linux: `flutter build linux --release`
- Release build Windows: `flutter build windows`
- Parity corpus tests: `flutter test test/parity`

Tests read the reference fixtures from `../tests/fixtures/` read-only; run
`flutter test` from any directory inside `flutter_app/`.

## Packaging

- Linux: `./scripts/package-flutter-linux.sh [version]` produces
  `dist/flutter-linux/<version>/ai-usage-monitor-flutter-linux-<version>.tar.gz`
  containing a relocatable release bundle.
- Windows: `powershell -File scripts/package-flutter-windows.ps1 [-Version x]`
  produces `dist/flutter-windows/<version>/ai-usage-monitor-flutter-win64-<version>.zip`.

## Architecture

Layered like the C++ core so parity can be tested per layer:

| Directory            | Contents (C++ equivalent)                       |
| -------------------- | ----------------------------------------------- |
| `lib/domain/`        | enums, `Metric`, `ProviderSnapshot`, decimal arithmetic, validation, aggregation (`domain.cpp`) |
| `lib/config/`        | settings/cache models, JSON codec, validation, atomic writes, data paths (`config.cpp`) |
| `lib/platform/`      | `HttpTransport`, `ProcessRunner`, `SecretStore`, `SingleInstanceSignal`, `Clock`, monitor service interfaces plus implementations (`platform.h`, `linux_platform.cpp`, `windows_platform.cpp`) |
| `lib/providers/`     | one adapter per provider kind plus parsers (`providers.cpp`) |
| `lib/scheduler/`     | refresh scheduler with reference backoff (`scheduler.cpp`) |
| `lib/presentation/`  | metric/health/freshness formatting, tooltip, overlay projection (`presentation.cpp`, `tooltip.cpp`, `overlay.cpp`) |
| `lib/ui/`            | dashboard, settings, tray, overlay widgets (`src/ui/`) |
| `lib/app_controller.dart` | orchestration equivalent to `MonitorApp`/`PublishSnapshots` (`ui/app.cpp`) |

Tests mirror those layers under `test/`.

## Dependencies and their role

| Package             | Role                                                            |
| ------------------- | --------------------------------------------------------------- |
| `tray_manager`      | system tray icon, menu and left-click activation                |
| `window_manager`    | frameless/always-on-top/skip-taskbar overlay window and dashboard always-on-top |
| `screen_retriever`  | monitor enumeration for overlay placement                        |
| `hotkey_manager`    | Windows `Ctrl+Alt+U` global shortcut for overlay recovery        |
| `win32` + `ffi`     | Windows FFI: overlay styles (`WS_EX_TRANSPARENT`, `MA_NOACTIVATE`, `HTTRANSPARENT`), full-screen suppression hooks, DPAPI secret store, single-instance mutex/event |
| `menu_base`         | tray menu item model (exposed by `tray_manager`)                 |

## Data contract

`settings.json` and `cache.json` are shared verbatim with the C++
application: same schema version, field names, serialization order (nlohmann
sorts keys; the Dart encoder sorts too for byte parity), validation rules and
protected credential tokens (`dpapi:…`, `secret-service:…`, `session:…`).

## Comparing against the C++ application

- Parity corpus: `test/parity/reference/` is generated by
  `scripts/parity-dump-reference.sh` and checked by `flutter test test/parity`;
  see `test/parity/README.md` for the full procedure.
- Side-by-side: point both apps at one shared data directory with
  `AI_USAGE_DATA_DIR` (edit configuration with only one app running; both
  rotate `.bak` and use distinct single-instance names).
